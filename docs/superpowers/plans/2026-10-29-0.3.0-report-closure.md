## Milestones and shipped scope

- [x] **M1 — F1: scheduling language**: deterministic weekday lists/ranges,
  reversed phrasing, several daily times sharing a minute, exactly representable
  minute/hour windows, optional cron-descriptor fallback, per-entry IANA zones,
  preview/create/edit UI. Unsupported grammar, multiple expressions, holiday
  calendars and a custom DST policy are deferred; Celery supplies DST semantics.
- [x] **M2 — F2: durable SQL definitions**: lazy optional SQLAlchemyBeatBackend,
  explicit initialization, stamping scheduler, CRUD, export, operation-scoped
  backend/code/SQL ownership, dry-run adoption/repair, snapshot conflict checks,
  and reviewed dashboard apply. Extra entries are never deleted. External writes
  can partially succeed; operators must inspect and replan after failure.
- [x] **M3 — F14: singleton runs**: LockProvider, Redis owner-token leases,
  track(singleton=...) with skip/retry conflicts, TTL renewal, bounded inspection
  and audited ownership-conditional administrative release API. There is no
  separate @singleton decorator or process-local production fallback. Lease loss
  cannot stop side effects and does not provide fencing. No lock dashboard ships.
- [x] **M4 — F12/F4/F6: alert depth**: durable beat owners, independent external
  dead-man pings at a bounded interval, stale-beat and individual/consecutive
  failure, stuck/lost, SLA, regression and digest rules, with dashboard choices.
  Stuck duration uses a fixed floor plus task-specific successful-run p95; lost
  workers use observed offline/stale age. Missing evidence remains unknown.
- [x] **M5 — F5/F7: digest and failure inbox**: minimum-sample p95 comparisons,
  runtime SLAs, per-task UTC daily outcome totals, durable incident-key delivery
  dedup, and acknowledge/ignore/reopen with actor/note/history in API/dashboard.
  A network timeout can duplicate notification delivery; exactly-once is not
  guaranteed. Depth rules bound candidate scans to matching runs in the relevant windows.
- [x] **M6 — F8/F13: identity and drift**: started-by-me/exact-initiator filters
  across list/count/export/bulk cancel and saved dashboard filters, acting-user
  retry identity, instrumented workflow publication inheritance, definition drift,
  unregistered tasks, missing historical entries and opt-in observed consumers.
  No arbitrary Redis keyspace orphan discovery/deletion ships.
- [x] **M7 — P2-14/P2-15/P2-17**: minute-bucket worker history with retention,
  authenticated range/paging and worker-card history/trend; DB-backed login
  backoff and newly issued browser-session revocation; validated all-or-nothing
  CSV pause import through CLI/admin API. Legacy cookies remain stateless until
  expiry/password reset/key rotation. The sidebar includes browser-session and singleton-lock dialogs; CSV import is available through the API/CLI.
- [~] **M8 — F10/P0-5**: /api/v1 aliases, OpenAPI contract and authenticated
  status-widget module ship. Existing schema isolation remains supported.
  Generated SDKs and configurable monitoring table prefixes are deferred.
- [~] **M9 — release integration**: detailed feature docs and dashboard surfaces
  listed above are implemented; release notes, packaging, static asset checks and the final local suite have passed (see docs/release-0.3.md). Remote/live CI and application rollout remain pending. Do not infer completion
  of live storage gates from local unit results or CI configuration.

## Explicit deferred scope

- [ ] Configurable monitoring table prefixes; use provisioned schemas, or separate
  SQLite files. Optional SQL scheduler tables have their own initialization and
  upgrade lifecycle.
- [ ] Generated language-specific SDKs.
- [ ] Arbitrary orphan Redis-key discovery/deletion, automatic keyspace cleanup,
  transactional cross-backend repair or automatic crash recovery.
- [ ] Unrestricted English, multiple cron expressions per entry, holidays and
  custom repeated/missing-local-time policy.
- [ ] Domain-specific failure summaries, resource fencing and guaranteed
  exactly-once side effects or alert delivery.
- [ ] Dedicated dashboard screens for beat-owner retirement and CSV pause import (documented APIs/CLI are available).

## Verification evidence and outstanding acceptance

Local owned-scope checks covered firing/recovery/unknown alert contracts,
heartbeat duplicate/out-of-order handling, retention, schema metadata agreement,
SQL reconciliation conflicts, timezone preservation and roles. The dashboard
build, frontend lint and strict documentation build have passed locally. The
parent release sweep records its final full-suite/package results separately.

The local browser smoke attempt could not launch Chromium under the filesystem
sandbox; a prepared smoke script is not a passing browser test. Live PostgreSQL,
MySQL and SQL Server storage contracts, real Redis lease contracts when skipped,
optional scheduler deployment contracts and a real application rollout remain
acceptance gates unless recorded as actually executed in the release evidence.
No local merge publishes a package; nothing is pushed by this work.

## Non-goals

Replacing Flower, Celery's result backend or a Prometheus stack is outside scope.
The metrics guide positions celery-exporter/Grafana as the complementary
observability layer. Definitions remain owned by the explicitly configured
backend; reconciliation does not install continuous code-to-backend syncing.
